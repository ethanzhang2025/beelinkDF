## 6. 关键设计沉淀汇总

### A. /chatbi → DF 跳转链路（原子化 useEffect）

```
chatbi 点跳转 → /?ws=<workspace>&table=<encoded_name>
  ↓
DataFormulator.tsx useEffect (一次 IIFE):
  if (ref.current) return;
  ref.current = true;
  (async () => {
    if (wantWs && activeWorkspace?.id !== wantWs) {
      const result = await loadWorkspace(wantWs);
      if (result.state) dispatch(loadState(...));
      else dispatch(resetForNewWorkspace({id: wantWs}));
    }
    await dispatch(loadWorkspaceTableByName(wantName)).unwrap();
  })().finally(() => history.replaceState 清 ws + table);
  ↓
state.tables.length > 0 → 主区切到 fixedSplitPane → 用户看到表卡 + 图表能力
```

### B. DeepSeek 服务端管理流

```
启动:
  model_registry._reload() → discover_providers (env _ENABLED=true)
                          → _maybe_autoenable_deepseek (兜底, 不需 _ENABLED)
                          → 注册 global-deepseek-deepseek-chat (endpoint=openai, api_key 服务端持有)

前端启动:
  thunk listGlobalModels → /api/agent/list-global-models（无 api_key 明文）
  dfSlice: selectedModelId == undefined → models[0].id = global-deepseek-deepseek-chat 自动选中

API 调用:
  前端 model_config.is_global=true 提交 →
  routes/agents.py get_client() → model_registry.get_config(id) 拿真实 api_key →
  OpenAI SDK with base_url=api.deepseek.com 调用
```

### C. Chart Insight 非 vision 模型防御

```
dfSelectors.getActiveModel → ModelConfig {supports_vision?: boolean}
visionDisabled = activeModel?.supports_vision === false (严格 false, undefined/true 放行)

三处入口同步 disabled + Tooltip：
  ① 顶部 chart-area 的 insight tab
  ② 底部 panel 已 insight 时的 regenerate
  ③ 底部 panel 无 insight 时的 generate insight

useFormulateData 自动触发：同条件守卫，不打后端
```

## 7. 战略决策点

### 现状诊断

POC-1 → POC-2C-lite + ChatBI + 轻语义层 + 智能问数外壳 + DeepSeek + 跳转链路 + 中文化 + gzip + schema 白名单**全跑通**。`feat/chatbi-native-df-integration` **领先 main 37 个 commit，未合并**。

### 下一步候选（按推荐优先级）

| # | 候选 | 改动量 | 收益 | 风险 |
|---|------|--------|------|------|
| **A** | **单 PR 合并 main**（含 v3.0+v4.0 全链路 37 commit）| 0 行 | 让稳定基线进主干，避免 PR 继续膨胀 | review 改动面大 |
| B | 栈式多 PR（按 v4.0 8 个 commit 拆）| 0 行 | 1 commit/PR review 友好 | 评审周期长 |
| **C** | **DF 原生页内置轻量 Ask 入口**（CLAUDE.md 暂存方向）| +200~400 行 | 不点按钮直接问数 → 进 DataThread；体验质变 | 中等，复用 chatbi 后端、不重写 /chatbi |
| D | DataAgent thinking 模型兼容 | +20-40 行 | 解锁 DeepSeek V4 Pro / R1 | 改 DataAgent 主循环 |
| E | 远程访问加速（Flask gzip 已做，可加 Brotli 或 nginx 前置）| +30-100 行 | 远程首次加载更快 | 中低 |
| F | beelink schema 白名单纳入更多类型（用户后续如发现新 type）| 1 行 | 兼容更多 beelink source 形态 | 需要每次探针确认 |
| G | 暂停等业务真用反馈 | 0 行 | 数据驱动 | 节奏停滞 |

### 最佳推荐：**A**（单 PR 合并 main）

**理由**：8 个 v4.0 commit 全部有真机验收 + build 通过；继续叠功能 commit 只让 PR 越来越大。合到 main 后 v4.0 成为正式起点，再做 C / D / E。

### 切换条件

- 选 **B**：组织 review 严格要求"一 commit 一 PR"
- 选 **C**：业务方明确要求 DF 内一站式问数（chatbi 不再作为主入口）
- 选 **D**：业务方明确要 DeepSeek V4 Pro/R1 进 DataAgent loop
- 选 **E**：远程访问首次加载体验仍不满足
- 选 **F**：用户在 beelink 后台加新类型 source 后又不显示
- 选 **G**：缺业务真实使用案例

## 11. 踩坑记录（v4.0 新增）

| # | 现象 | 原因 | 解法 |
|---|------|------|------|
| 1-22 | 见 v3.0 §11 | — | — |
| **23** | 跳转后 DataFormulator.js 缓存导致老用户首屏仍英文 | i18n 已选 `i18nextLng=en` 存 localStorage | i18n init 强制 `localStorage.setItem('i18nextLng','zh')` 覆盖 |
| **24** | dispatch loadState 把 `state.tables` 重置成 saved.tables 空数组导致 landing 重显 | loadState 用 saved 全替换 state 字段 | 用 `resetForNewWorkspace`（保留 globalModels/selectedModelId/settings 同时清 tables）替代 setActiveWorkspace |
| **25** | useEffect 重跑驱动两步状态机偶尔 race，step2 不触发 | activeWorkspace 改变与 IIFE 异步 dispatch 时序 | 改成一次 IIFE 串行 await，`chatbiHandledRef` boolean 一次性消费 |
| **26** | Chart Insight 后端报 "model does not support image input" 噪音 | 用户拿 deepseek-chat 文本模型点 Chart Insight | 前端 `supports_vision === false` 时三处入口全部 disabled + tooltip + 自动触发跳过 |
| **27** | `Cache-Control: no-cache` 让 hashed assets 每次发 304 验证 | Flask `send_from_directory` 默认 no-cache | after_request 对 `/assets/*` 加 `immutable` 长缓存 |
| **28** | Flask `send_from_directory` 返回 direct_passthrough 响应，`response.get_data()` 拿不到 body | direct_passthrough 默认 True | 在 after_request 里 `response.direct_passthrough = False` 强制读 body |
| **29** | catalog cache 文件存的是 3 source（test/smartquery_demo/tpcds_sf10）让前端永远显示 3 个 | 旧 cache 没失效 | 修复 `_CONTAINER_TYPES` 后必须 `rm catalog_cache/*.json` 重新拉一次 |
| **30** | `mysql` source 拉 catalog tree 耗 60+ 秒（2149 张表）超出 sidebar 默认 fetch timeout | 表数量级太大 | 后端 API 已 OK；前端 sidebar 渲染慢是另一题，未在本轮处理（属"远程访问加速"E 候选范围）|
| **31** | bash kill DF 进程后立即查 pgrep 仍能看到 PID | 是 pgrep 自身的 bash 父进程 | curl http 验证服务是否真停，不要看 pgrep |
