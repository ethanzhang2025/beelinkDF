## 1. 项目极简 30 秒读完

把 **beelink（基于 Dremio v25 二开）** 接入 **Data Formulator (DF, microsoft/data-formulator v0.7-alpha.2)** 作为原生数据源。DF 当智能图表主体，beelink 当唯一数据源和权限裁决方。三阶段演进：

* **POC-1**：UI 选表导入 → 落 DF workspace → 拖图 ✅ **已完成 + 真机验收通过**
* **POC-1.5**：手写 Dremio SQL 直通 → 结果回 workspace ⏸ 未开始
* **POC-2**：自然语言 → Dremio SQL → 直通执行 ⏸ 未开始

beelink 一行 Java 都不用改（POC 全程靠它原生 `/apiv2/login` + `/api/v3/{catalog,sql,job}`）。

## 6. 关键设计沉淀汇总（跨工作包共通模式）

### A. DF connector 框架的"零代码集成"承诺被验证

写 1 个 loader 类 + 注册 1 行 `_LOADER_SPECS` → 自动获得：

* 25+ 个 `/api/connectors/*` REST 端点（list / create / connect / get-catalog-tree / sync-catalog-metadata / preview / import / refresh / delete / column-values / 等）
* per-identity loader 实例隔离 + Vault 加密凭证持久化 + 自动重连
* 4 种 auth 模式：`credentials / sso_exchange / delegated / oauth2`
* `ServerConfig.CONNECTORS` 注入前端 → UI 卡片 + 表单 + catalog 树自动渲染（**前端零改动**）
* DataAgent `search_data_tables` 走磁盘 catalog 缓存自动检索（POC-2 schema 注入路径免费）

`app.py` 完全不用改（与 v10 初版预测不符 —— `register_data_connectors` 仅挂 admin-pinned；普通 loader 走 `DATA_LOADERS` 自动 discovery + UI 自建实例）。

### B. beelink REST 三个易踩坑事实

| # | 坑 | 真相 |
|---|---|---|
| 1 | `@Path("/login")` 看着是 `/login` | JAX-RS Application 前缀 `RestServerV2.java:40 pathSpec="/apiv2/*"` →  真实 URL `/apiv2/login` |
| 2 | `SELECT 1 AS one` 看着无害 | Dremio Calcite 把 `one/two/three/day/month/year/level/value` 当保留字 → `SELECT 1 AS n` 才稳 |
| 3 | "拿结果给我 5000 行" | `JobResource.java:125 Preconditions.checkArgument(limit <= 500)` 硬上限；必须分页 |

### C. DF connector REST body 字段命名

* `POST /api/connectors`（创建实例）：`{loader_type, source_id, display_name, params}`
* 其余共享动作端点（get-catalog-tree / preview-data / import-data / refresh-data / column-values 等）：`{connector_id, ...}`
* `connector_id` 真实格式：`<loader_type>:<safe-source-id>`，例 `beelink:beelink-main`（dash 不是 underscore；`source_id="beelink_main"` 被规范化）
* `import-data` 前置：必须 `POST /api/sessions/create` + 后续请求带 `X-Workspace-Id` 头

### D. beelink token 头协议

* 自定义：`Authorization: _beelink<token>`（`TokenUtils.java:27`，**无空格**）
* 标准：`Authorization: Bearer <token>` 也支持
* `UserLoginSession`：`{token, userName, userId, expires(ms), admin, roleId, orgId, permissions, ...}`

### E. POC 性能边界

* 默认 `import_options.size = 10000`（20 页 × 500）≈ 1-2 秒
* DF 框架硬上限 `MAX_IMPORT_ROWS = 2_000_000`（`external_data_loader.py:10`）
* `_LIST_TABLES_MAX_NODES = 5000` 防止误用打满 beelink

## 7. 战略决策点

### 现状诊断

POC-1 端到端通了，文档与代码一致，分支领先 main 3 个 commit。**接下来要选下一步动作**。

### 候选

| # | 候选 | 改动量 | 收益 | 风险 |
|---|------|--------|------|------|
| **A** | **开 PR 把 `feat/beelink-poc1-loader` merge 到 `main`** | 0 行代码 | POC-1 成果落主干，给业务方稳定接入 | merge 后再切新分支推进 POC-1.5（最干净） |
| B | 直接在当前分支推进 POC-1.5（手写 SQL 直通） | +200-400 行（新端点 `/api/beelink/sql/execute` + 前端 SQL 编辑器入口） | 不切分支、连贯推进 | 分支变长、PR 评审会更费劲 |
| C | 切新分支 `feat/beelink-poc1.5-sql` 推进 POC-1.5 | 同 B | 干净；POC-1 分支冻结 | 多分支管理成本 |
| D | 转去做 Phase 5 图表体验打磨（DictTable 卡片显示 source_query 摘要、错误样式优化等） | +100-200 行前端 | UX 立刻提升 | 触碰前端，与"不动前端"原则有微妙张力 |
| E | 暂停在 POC-1，让业务真用一段时间收集反馈再定方向 | 0 | 数据驱动后续决策 | 节奏停滞 |

### 最佳推荐：**A（先开 PR）→ 然后 C（新分支推进 POC-1.5）**

**理由**：
1. POC-1 已经"端到端 PASS + 文档与代码一致"，符合 merge 标准；
2. 开 PR 让团队 review 一次 BeelinkDataLoader（外科手术式 560 行 + 1 行注册），比把它埋在长分支里更易把关；
3. POC-1.5 是独立增量功能（新端点、不动 loader 核心），适合新分支；
4. 选 C 而非 B 是因为分支语义更清晰（一次 PR 一个 phase）。

**切换条件**：
* 选 **B** 当且仅当：业务方非常急要 SQL 直通、PR 评审节奏跟不上、且能接受 PR 变长
* 选 **D** 当且仅当：POC-1 已经被业务方实际用上、明确报出"图表体验差"作为最大痛点
* 选 **E** 当且仅当：当前没有具体业务案例驱动、需要数据先

## 11. 踩坑记录（实测过的）

| # | 现象 | 原因 | 解法 |
|---|------|------|------|
| 1 | `POST /login` 返回 HTML 而非 JSON | beelink 8998 端口是 SPA，`/login` 是前端 route；REST 真路径是 `/apiv2/login`（`RestServerV2.java:40 pathSpec="/apiv2/*"`） | 全部 `/login` 改 `/apiv2/login` |
| 2 | `SELECT 1 AS one` 报 `Encountered "AS one"...` | Calcite 把 `one` 当保留字 | 用 `SELECT 1 AS n`；避 `one/two/three/day/month/year/level/value` 等 |
| 3 | `POST /api/connectors/import-data` 报 `INVALID_REQUEST: No active workspace` | 未建 workspace 也未带 `X-Workspace-Id` 头 | 先 `POST /api/sessions/create {"id":"default"}` + 后续请求加 `-H "X-Workspace-Id: default"` |
| 4 | `POST /api/connectors/get-catalog-tree {source_id:...}` 报 `connector_id is required` | DF 共享动作端点 body 字段是 `connector_id` 不是 `source_id` | 用 `{"connector_id":"beelink:beelink-main", ...}` |
| 5 | 创建实例时 `source_id="beelink_main"` 但后续访问 `connector_id="beelink:beelink_main"` 找不到 | 后端把 underscore 规范化为 dash | 用 `connector_id="beelink:beelink-main"`（DataConnector 返回的 id 字段为准） |
| 6 | DF Flask 进程被 background bash 命令一起 kill（exit 144） | bash tool 的 background 机制把子进程绑到 parent shell | `setsid + < /dev/null + > /tmp/log 2>&1 & disown` 完全脱离 |
| 7 | `npm install` 报 ERESOLVE peer dep 冲突 | DF 项目锁文件是 yarn，npm 解析不出来 | `npm install --legacy-peer-deps`；装完别忘 `git checkout HEAD -- yarn.lock` 恢复 |
| 8 | DF 首屏 "First, let's Select Models" 模态拦住所有交互 | 未配 LLM 时 DF 强引导 | 不影响 connector 功能；UI 验证时用 JS `display:none` 该模态再点 sidebar |
| 9 | `python -m data_formulator` 报 `No module named` 但 `import data_formulator` 可用 | venv `pip install -e .` 实际成功，但 background bash 命令 race 了 | 直接前台启动或等 pip 完全完成 |
| 10 | `/api/v3/job/{id}/results?limit=5000` 报错 | `JobResource.java:125 Preconditions.checkArgument(limit <= 500)` 硬上限 | BeelinkDataLoader 已做 `_BEELINK_PAGE_SIZE = 500` 自动分页 |
