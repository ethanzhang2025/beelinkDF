### 各 Core 真实交付（v3.0 新增 / 变更）

* **DataAgent Core**（`agents/data_agent.py`，2320 行，+15 行）：
  - `__init__` 增 `self._beelink_sql_cache: dict[tuple[str, str], dict] = {}`

  - 不影响第一次调用、不影响 POC-1/1.5/2A 任何路径

* **ChatBI Blueprint**（`chatbi_demo.py`，1069 行）：
  - `GET /chatbi` 返回单页 HTML（独立蓝图，不进 React/Vite）
  - `GET /chatbi/llm-defaults` 报告 `{has_key, endpoint, model, api_base}` — **不返 key 明文**
  - `POST /chatbi/agent-stream` 从 env `DEEPSEEK_API_KEY` 注入 + 用 stdlib `urllib` 流式转发到 `/api/agent/data-agent-streaming`，透传 `X-Identity-Id` / `X-Workspace-Id`
  - `GET /chatbi/semantic?source=<name>` 加载 `semantic/<source>.yaml` 返回精简 prompt + 原始 raw 对象
  - 前端通用 4 类路由（按优先级，全程不调 LLM 除最后一类）：
    1. `isSampleTableIntent`（前 N 行 / 样例 / sample / preview）→ `/api/connectors/preview-data` rows
    2. `isDescribeTableIntent`（字段 / 列名 / 表结构 / schema / describe）→ 同端点 columns + `inferColumnPurpose` 通用规则推测含义
    3. `isSimpleAggregateIntent`（按 X 统计 / X 分布 / X 占比）→ 并发 preview-data 探查含字段的表 → 唯一表生成 `SELECT "<f>", COUNT(*) AS cnt ... ORDER BY cnt DESC` 走 `/api/connectors/import-sql` → 渲染条目化 headline + 表 + 柱状图

    5. 其他 → `runDataAgent` 走 `/chatbi/agent-stream` 服务端代理；自动 fetch `/chatbi/semantic` 把 prompt 注入 guardrail
  - 通用 `maybeChart`（单分类 + 单数值 → 柱状图，无列名硬编码）+ `inferUnit`（语义匹配 客户数→人 / 订单数→单 / 金额→元 / 数量→件 / 否则空）

## 6. 关键设计沉淀汇总

### A. ChatBI 路由优先级（不调 LLM 的 4 类）

```
sample_table > describe_table > simple_aggregate > list_tables > DataAgent
```

* 字段查询（含"字段/列/schema/describe"）反否决"列出表"（关键词"列"易冲突）
* 表名解析优先 `<source>.<name>` 模式，否则在运行时缓存 `state.tables`（首次 list_tables 后填充）
* simple_aggregate 找表逻辑：**并发**对 source 所有表调 preview-data；只看 columns 是否含 field；0/1/多三分支

### B. 服务端代理避免浏览器持有 key

* env `DEEPSEEK_API_KEY` 由 DF 服务端读
* 前端 `SERVER_HAS_KEY` 启动探测，决定是否隐藏字段 + 切换 streamUrl
* stdlib `urllib` 流式转发：`response.read(4096)` 循环 yield，避免引入 requests 依赖
* `/chatbi/llm-defaults` 永远不返 key 明文，仅返元数据

### C. 语义层 prompt 格式

* 紧凑文本（一行一表、一行一 join、一行一 metric），避免噪声
* 末尾固定 Rules：仅用列出的表/列；优先直查 SELECT 而非 INFORMATION_SCHEMA；缺字段说清楚
* 仅注入 DataAgent 分支；其他 4 类路由完全不依赖

### D. 单位推测规则（避免错配）

```
customer_count / 客户数 / 人数        → 人
order_count / 订单数 / 单数 / 笔数    → 单
amount / sales / revenue / 金额       → 元
quantity / qty / 数量 / 件数          → 件
未命中 → 不加单位（宁可不加也不错配）
```

## 10. 一行命令速查

```bash
# ── 环境 ───────────────────────────────────────
cd ~/beelinkDF && source .venv/bin/activate
git branch --show-current && git log --oneline -5

# ── 启 DF（当前绑 0.0.0.0:5500 允许外网访问）─────
nohup setsid .venv/bin/python -m data_formulator --port 5500 --host 0.0.0.0 \
  < /dev/null > /tmp/df.log 2>&1 &
disown
sleep 6 && curl -s --max-time 3 -o /dev/null -w "%{http_code}\n" http://127.0.0.1:5500/

# 仅本机演示则用：--host 127.0.0.1（更安全，演示完务必改回）

# ── 关 DF ──
PIDS=$(pgrep -f "data_formulator.*--port 5500"); [ -n "$PIDS" ] && kill $PIDS

# ── ChatBI 演示（浏览器，零 npm/build）──
# 浏览器开 http://127.0.0.1:5500/chatbi 或 http://vvsvr:5500/chatbi
# 服务端已配 DEEPSEEK_API_KEY → api_key 字段自动隐藏

# ── /chatbi 自检（含语义层）──
curl -s http://127.0.0.1:5500/chatbi/llm-defaults
# 期望 {"has_key":true,"endpoint":"openai",...}（不含 key 明文）
curl -s "http://127.0.0.1:5500/chatbi/semantic?source=smartquery_demo" -o /tmp/sem.json
python3 -c "import json; print(json.load(open('/tmp/sem.json'))['has_semantic'])"
# 期望 True

# ── /chatbi 4 类路由通用验收（不调 LLM 的前 4 类）──
# 浏览器在 /chatbi 输入问题（POC-2A/2B/2C-lite 全验证过）：
#   "smartquery_demo 有多少张表？"      → list_tables（6 张表）
#   "customers 表有哪些字段？"          → describe_table（6 字段）
#   "看 products 前 5 行"               → sample_table（10 行）
#   "按 gender 统计客户数"              → simple_aggregate（女 989 人/...）
#   "各渠道订单数是多少？"              → DataAgent + 语义层（抖音 2041 单/...）

# ── 命令行直调 streaming（旧路径，需手填 key）──
H='-H X-Identity-Id:local:beelink -H X-Workspace-Id:default -H Content-Type:application/json'
curl -s $H http://127.0.0.1:5500/api/connectors >/dev/null
jq -n --arg key "$DEEPSEEK_API_KEY" \
  '{model:{endpoint:"openai",model:"deepseek-chat",api_key:$key,
           api_base:"https://api.deepseek.com",api_version:null,is_global:false},
    input_tables:[], primary_tables:[],
    user_question:"看下 smartquery_demo.customers 各 gender 客户数。"}' \
  | curl -s --max-time 180 $H -X POST http://127.0.0.1:5500/api/agent/data-agent-streaming -d @-

# ── 语法 + 注册自检 ──
.venv/bin/python -m py_compile \
  py-src/data_formulator/chatbi_demo.py \
  py-src/data_formulator/agents/data_agent.py \
  py-src/data_formulator/data_connector.py
.venv/bin/python -c "from data_formulator.agents.data_agent import TOOLS; \
                     print([t['function']['name'] for t in TOOLS])"
# 期望含 query_beelink_sql

# ── 分支切换 ──
git checkout feat/beelink-poc1-loader              # POC-1 基线 e408adf
git checkout feat/beelink-poc1.5-sql-pass-through  # POC-1.5 基线 82baa3d
git checkout feat/beelink-poc2-nl2sql              # POC-2A 基线 40f2fc4
git checkout feat/beelink-poc2b-dataagent-tool     # ★ v3.0 当前 7f7b74a
```

## 11. 踩坑记录（v3.0 新增）

| # | 现象 | 原因 | 解法 |
|---|------|------|------|
| 1-14 | 见 v2.0 §11 | — | — |
| **15** | RTK 包装的 curl 用 `> /tmp/file` 落盘只 582 字节 | RTK 流式截断 stdout | 改用 `curl -o /tmp/file ...`，绕过 stdout 截断 |
| **16** | DF 重启后 `/chatbi` 第一次列表表返 0 张 | connector 注册表为空，未触发 lazy-load | `runListTablesIntent` / `runListColumnsIntent` 入口先 GET `/api/connectors` |
| **17** | "按 gender 统计客户数" DataAgent 走偏先查 INFORMATION_SCHEMA | guardrail 写"先查 catalog 再 SELECT"过强引导 | 改为鼓励"直接 SELECT，失败再 INFORMATION_SCHEMA" |
| **18** | 表清单意图正则漏"多少张/几张" | 原正则只覆盖"有哪些/列出/清单" | 扩展含 `多少张|多少个|几张|几个表|how many` |
| **19** | DataAgent headline 一律加"人" 误显示订单数为"人" | 原 `/cnt|count|num|qty|total/` → "人" 单一规则 | `inferUnit(valueCol)` 按语义匹配：customer→人 / order→单 / amount→元 / qty→件 |
| **20** | "字段查询" 正则与"列出表" 互相干扰（"列"字易冲突）| `isListTablesIntent` 含"列出表" | 优先级排序：字段意图先判断，"列出表" / "表清单" 在字段意图分支显式否决 |
| **21** | bash kill 后台 DF 后下一句 setsid 起 DF 偶尔 SIGHUP | `kill + setsid` 同一 bash 调用，shell 退出顺手带走 | 拆两步 bash 调用：① 关 ② 起 |
| **22** | bash setsid 起 DF 后 sleep + curl exit 144 | bash 异常退出码 144 实际是 DF 后台被 SIGHUP（已 spawn 但子 shell 退出） | 用 `nohup setsid + < /dev/null + > /tmp/log 2>&1 & disown` 三件套+独立 bash 调用 |
