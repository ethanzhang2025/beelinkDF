## 6. 关键设计沉淀汇总

### A. POC 阶段分层

| 阶段 | 谁生成 SQL | 谁执行 | 谁裁权 |
|---|---|---|---|
| POC-1（表导入） | DF 自动 `SELECT * FROM ...` | beelink | beelink |
| POC-1.5（手写 SQL） | **用户手写** | beelink | beelink |
| POC-2A（独立 NL2SQL API） | **LLM（DF 后端单次调）** | beelink | beelink |
| POC-2B（DataAgent tool） | **LLM（DataAgent 自循环）** | beelink | beelink |

DF 始终是图表主体；beelink 始终是数据源 + 权限裁决方；LLM 始终不参与数据。

### B. LLM 兼容性矩阵（DeepSeek）

| Model | 类型 | POC-2A 单次调用 | POC-2B DataAgent 自循环 |
|---|---|---|---|
| `deepseek-v4-pro` | thinking（V4） | ✅ | ❌（reasoning_content 需回传，DataAgent 主循环不处理）|
| `deepseek-v4-flash` | thinking（V4） | ✅ | ❌（同上） |
| **`deepseek-chat`** | V3 非 thinking | ✅ | ✅ **推荐 POC-2B 用** |
| `deepseek-reasoner` | thinking（V3） | ✅ | ❌（同上） |

**关键事实**：DataAgent `_call_llm_once`（`data_agent.py:1838`）取 `resp.choices[0].message.content`，不处理 `reasoning_content` 字段。修复需改 DataAgent 主循环，已明确**留待 POC-2C 之后**。

### C. 错误码语义对应

| 错误来源 | classifier | 错误码 | retry |
|---|---|---|---|
| 缺 connector_id / question / sql / table_name / model | `INVALID_REQUEST` | INVALID_REQUEST | false |
| connector 不存在 | `_resolve_connector` | CONNECTOR_ERROR | false |
| LLM API 401（错 api_key）| `classify_and_wrap_llm_error` | **LLM_AUTH_FAILED** | false |
| LLM API 429 | 同上 | **LLM_RATE_LIMIT** | **true** |
| LLM API timeout / 反复非 JSON | 同上 | LLM_TIMEOUT / LLM_UNKNOWN_ERROR | true / false |
| LLM 生成非 SELECT | `_is_select_or_with` | INVALID_REQUEST | false |
| beelink 401（凭证失效，重登也失败）| `classify_connector_error` | CONNECTOR_AUTH_FAILED | false |
| beelink 403 | 同上 | ACCESS_DENIED | false |
| beelink SQL 错（列名/表名）| 同上 | DB_QUERY_ERROR | false |
| beelink job 超时（含英文 timeout 关键词）| 同上 | **DB_CONNECTION_FAILED** | **true** |
| workspace 缺 X-Workspace-Id 头 | DF 框架 | INVALID_REQUEST | false |

### D. catalog_cache 路径修正

**真实路径**：`<workspace.user_home>/catalog_cache/<safe_source_id>.json`（**单 JSON 文件**，含 `{source_id, synced_at, tables[...]}`）

`safe_source_id(":")` → `--`、`/\` → `_`。例：`"beelink:beelink-main"` → 文件 `catalog_cache/beelink--beelink-main.json`

v10 doc §3.7 已修正（v10 初稿误写为"子目录每表一文件"）。

### E. workspace 表名鲁棒性

POC-2B 引入：`workspace.get_fresh_name(table_name)` 自动加 `_2/_3` 后缀避免覆盖。这是 POC-2A `run_nl2sql` 行为的小变化（原本同名覆盖 → 现自动加后缀），已在 §14.9 说明。

## 7. 战略决策点

### 现状诊断

POC-1 → POC-1.5 → POC-2A → POC-2B 四阶段全通；DataAgent 在 DeepSeek Chat 下 NL→SQL→执行→落 workspace→后续 explore/visualize 闭环出图。
四个分支栈式存在，**未合并 main**。

### 下一步候选

| # | 候选 | 改动量 | 收益 | 风险 |
|---|------|--------|------|------|
| **A** | **栈式开 PR：4 个分支依次合并 main**（poc1 → poc1.5 → poc2-nl2sql → poc2b）| 0 行代码 | 全成果落主干 | 4 个 PR 评审周期；冲突解决 |
| **B** | **单 PR 把 poc2b 直接 merge 到 main**（含全部 4 阶段历史） | 0 行代码 | 1 个 PR | review 改动面大（POC-1/1.5/2A/2B 全部出现在一个 PR） |
| C | 在当前分支推进 POC-2C 错误修复自循环增强 | +30-80 行 | LLM 自修体验提升 | 用例 2 已证既有 max_tool_rounds=12 够用，收益不大 |
| D | 切新分支做 DataAgent thinking 模式兼容（处理 reasoning_content 回传） | +20-40 行 | 解锁 deepseek-v4-pro/r1 在 DataAgent | 改 `_call_llm_once` 主循环，影响所有 DataAgent 用法 |
| E | Phase 5 图表体验打磨（DictTable 卡片显示 source_query 摘要、错误样式、前端 NL2SQL 入口）| +200-500 行前端 | UX 提升 | 触碰前端，破"不改前端"原则 |
| F | 暂停在 POC-2B 等业务真用 | 0 | 数据驱动后续 | 节奏停滞 |

### 最佳推荐：**B（单 PR merge POC-2B 到 main）** 然后视业务反馈定 D 或 C

**理由**：
1. POC-1 → POC-2B 是连贯演进，每一步都已 commit + 真机验收 + 文档回写一致；
2. 四个独立 PR 评审 4 次会产生重复 context（每个 PR 都要重新解释 POC 边界）；
3. 单 PR 评审 1 次能让 reviewer 完整看到 POC 链路；
4. merge 后再决定是否做 D（DataAgent thinking 兼容）—— 这是真正能解锁更强模型的改进。

**切换条件**：
- 选 **A** 当且仅当：组织 review 流程严格要求"一个 commit 一个 PR"
- 选 **D** 当且仅当：业务方明确要求用 DeepSeek V4 系列 reasoning 模型做更复杂 NL2SQL
- 选 **E** 当且仅当：业务方已实际投用并明确报"图表体验差"
- 选 **F** 当且仅当：缺业务真实使用案例

## 11. 踩坑记录（实测过的）

| # | 现象 | 原因 | 解法 |
|---|------|------|------|
| 1 | `POST /login` 返回 HTML | beelink SPA 把 `/login` 当前端 route；REST 真路径是 `/apiv2/login` | 全部 `/login` → `/apiv2/login` |
| 2 | `SELECT 1 AS one` 报错 | Calcite 把 `one` 当保留字 | 用 `SELECT 1 AS n`；避 `one/two/three/day/month/year/level/value` |
| 3 | `import-data` 报 `No active workspace` | 未建 workspace + 未带 `X-Workspace-Id` | 先 `POST /api/sessions/create {"id":"default"}` + 后续带头 |
| 4 | `get-catalog-tree` 报 `connector_id is required` | body 字段是 `connector_id` 不是 `source_id` | 用 `{"connector_id":"beelink:beelink-main"}` |
| 5 | `source_id="beelink_main"` 但访问 `connector_id="beelink:beelink_main"` 找不到 | 后端 underscore 规范化为 dash | 用 `beelink:beelink-main`（DataConnector 返回 id 字段为准） |
| 6 | DF Flask 被 background bash 一起 kill（exit 144）| bash background 把子进程绑到 parent shell | `nohup setsid + < /dev/null + > /tmp/log 2>&1 & disown` |
| 7 | `npm install` ERESOLVE 冲突 | 项目锁文件是 yarn | `npm install --legacy-peer-deps`；装完 `git checkout HEAD -- yarn.lock` |
| 8 | 首屏 "Select Models" 模态拦交互 | 未配 LLM 时强引导 | 不影响 connector；UI 验证可用 JS `display:none` |
| 9 | `/job/{id}/results?limit=5000` 报错 | `JobResource.java:125 Preconditions.checkArgument(limit <= 500)` 硬上限 | BeelinkDataLoader 已自动 500/页 |
| 10 | catalog cache 路径 doc 错 | v10 初稿写"子目录每表一文件" | 实际是 `<workspace_root>/catalog_cache/<safe_source_id>.json` 单文件；§3.7 已修 |
| 11 | DeepSeek V4 系列调 DataAgent 报 400 reasoning_content | thinking 模式 / DataAgent `_call_llm_once` 不处理 reasoning_content 回传 | POC-2B 改用 `deepseek-chat`；改 DataAgent 主循环留待后续 |
| 12 | POC-2A LLM 错被 connector classifier 误归 CONNECTOR_AUTH_FAILED | `_call_llm_for_sql` openai/litellm 异常之前走 `classify_and_raise_connector_error` | POC-2A 加固：新增 `NL2SQLLLMError` + endpoint 走 `classify_and_wrap_llm_error` |
| 13 | POC-2B DataAgent connector lazy-load 未触发 → "Connector not found" | DF 重启后 `_user_connector_key` 注册表为空，需先调一次 `GET /api/connectors` 触发 vault auto-reconnect | curl 端到端时先 `GET /api/connectors` 再发 DataAgent 流 |
| 14 | POC-2A 同 table_name 第 2 次跑 → 表名变 `_2`（行为微变化）| POC-2B 引入 `workspace.get_fresh_name` 避免覆盖；POC-2A run_nl2sql 共享 helper 后也走此分支 | 已在 §14.9 说明；用户明文要求"避免覆盖" |
